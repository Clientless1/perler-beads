# 云端数据与微信内容审核

## 当前 2.0.0 数据流

原始照片在设备检测、主体提取和取样，不直接上传。登录后的逐格图纸（可能反映照片内容）、作品名、进度、库存、订单、昵称和客服内容会发送到开发者 API，并保存至 PostgreSQL。平台不提供客户间公开作品社区；这不等于无需履行内容审核与隐私义务。

本地图片模型继续执行，但不能代替微信官方内容安全 API。此前驳回涉及的官方接口尚未接入当前客户端，当前版本未上传或提审，不能声称审核问题已解决。`server/` 顶层历史适配器与云业务服务独立，需要按真实平台要求重新接入、配置并等待最终检测结果。

正式发布前须按真实经营主体填写联系方式、服务条款、保存期限和账号删除处理方式；更新微信隐私保护指引、登录/请求/下载合法域名、服务类目、收费和退款规则；使用真实凭据核验登录、支付与内容检测。不要沿用纯本地版「无服务器、无数据上传」的复核文案。

## 1.0.3 历史说明

以下仅记录旧版本，不代表当前云端数据流。

## 当前实现：1.0.3

小程序不需要服务器、HTTPS 检测域名、微信云开发或 AppSecret。新增本机色情图片识别，检测通过后才放行；模型不可用或检测失败会停止照片流程。没有伪造“微信检测通过”的标记。本地识别模型与微信安全接口是不同的机制，详见[本地图片内容检测](LOCAL_IMAGE_SAFETY.md)。

| 数据 / 功能 | 当前处理方式 |
| --- | --- |
| 相册照片、拍照、换图 | 使用微信选图接口取得本机临时文件；本机解码和内容检测，通过后才预览 |
| 主体提取 | 包内 U2Netp 模型在手机推理；模型解压及缓存均为本地文件；可手动修整 |
| 取样、配色、图纸生成 | 手机画布与 JavaScript 本地计算 |
| 作品名、逐格图纸、进度 | 仅写入当前设备的小程序存储，最多 20 份；不保存原始照片到作品库 |
| 图纸 / 成品导出 | 先检查图纸，再由本机画布生成 PNG，经用户操作保存到本机相册 |
| 样板 | 640 份图案、封面、色卡和来源随包提供，不在线获取 |
| 用豆清单 | 用户主动复制至本机剪贴板 |
| 发布 / 社区 / 同步 | 没有用户作品公开展示、发布、云同步或开发者服务器上传功能 |

H5 版本从自身静态站点读取模型及 WASM，选取的照片仍在浏览器本地处理。不能将“本地处理”表述为 H5 第一次访问完全无需网络。微信版本资源随主包和主体分包提供；首次获取安装包/分包由微信完成，不能承诺新设备首次使用完全断网也能加载。

旧版本本机记录保留名称和制作进度，缩略图及打开图纸需先通过新的本地检测。旧检测标记不参与放行；新记录不写入检测通过标记。缓存仅存在内存，按实际格子颜色、模型与规则版本匹配。

## 审核状态

微信于 2026-11-05 对图片功能提出接入内容安全接口的要求。当前新增了本地图片识别，但**并未接通微信内容安全接口，也未解决或保证通过这次审核**。可如实写“已加入本地模型检测”，不能写“已接入微信检测接口”或“纯本地自动免审”。

此前普通 Node.js 检测服务及测试仍保留在 `server/`，完全不被小程序引用或构建。历史部署参考见 [历史可选方案](LEGACY_CONTENT_SAFETY_SERVER.md)。未来如微信明确仍要求在线检测，需要另外选择并接通后端，更新告知和隐私说明，并重新做真实联调；当前不自动启用该方案。

## 可提交的复核说明

> 本小程序“照片生成拼豆图纸”为设备本地图片处理工具。用户选择或拍摄的照片仅在当前设备用于预览、主体提取、取色和生成拼豆图纸，不上传开发者服务器或云函数。作品名称、图纸及制作进度仅保存在当前设备；用户主动导出的图纸保存到本机相册。产品不提供用户内容发布、社区展示、用户间内容传播或云同步功能，内置样板随安装包提供。请协助复核此类本地处理场景是否仍须接入内容安全接口；如需接入，请指出具体功能入口和适用要求，以便准确整改。

只能在最终提交版本与上述实现一致时使用这段说明。微信平台隐私保护指引应按实际使用的选图、相册保存等接口如实填写，不能因未上传照片而省略平台要求的声明。

## 提交前检查

1. 运行 `npm test`、H5 构建、微信构建，确认产物更新。
2. 在微信真机测试相册、拍照、取消再选择、换图、提取主体、生成图纸、改名、复制清单和两种导出；允许/拒绝相册权限后应可恢复。
3. 生成一份作品，重启小程序后检查名称、缩略图和制作进度；旧版记录也应可打开。
4. 加载主包与主体分包后，在离线状态重复测试核心流程。首次分包获取与开发者工具真机调试连接不属于应用的照片上传。
5. 用网络面板核查照片、图纸和名称没有业务上传请求；确认没有云开发和检测服务配置。
6. 由维护者向微信申请复核，收到反馈后再决定提审路线。此次本地修改本身不是重新上传或提审。
