# 本地图片内容检测 · 2026-11-11

按维护者要求新增色情图片检测，保持照片仅在设备处理；未开通云服务、未上传照片、未发布或提审。本地模型不是微信内容安全 API，不能据此宣布已满足此前接口要求或保证审核通过。

## 运行方式

- 固定使用 NSFWJS 的 MobileNetV2 五分类模型，来源版本、校验值见 `src/data/safety-model.json`，授权见 `licenses/NSFWJS-MIT.txt`。使用实际神经网络推理，不以肤色比例、文件名或免责声明代替识别。
- 微信优先通过 `wx.createInferenceSession` 推理，模拟器、不支持原生推理或原生加载/运行失败时，使用独立微信 Worker 执行同一模型，自带 WASM 卷积加速；Worker/WASM 不可用时分别退回主线程分段 CPU / Worker CPU。三个 gzip 模型资源以 Base64 JS 模块放在普通分包中，合计约 4.11 MiB，通过小程序 `require.async` 加载后使用自带 fflate 解压，不依赖小游戏 `loadSubpackage`、`readCompressedFile` 或代码包二进制文件读取；拼接为约 10 MiB 的普通 float32 ONNX，并使用版本化文件及 MD5 检查缓存完整性。首次取得分包需要网络，图片不会随分包下载上传。
- H5 使用自身站点的模型与 ONNX Runtime WASM，在 Worker 中推理。不得把 H5 静态资源请求描述成“首次访问完全离线”。
- 微信开发者工具可通过兼容 CPU 推理完成选图和检测，不跳过检测。兼容检测优先在后台线程运行；无 Worker 的旧环境使用分段 CPU 让出页面，速度取决于设备；真机性能和原生推理兼容性仍需扫码验证。若资源读取、推理或完整性校验失败，仍会停止该次照片流程，可取消或重新选图。
- 微信原生桥接可能返回另一个 JavaScript 运行环境的 ArrayBuffer / Float32Array；通过内置类型校验识别，不能用 `instanceof` 判断。否则完整的模型会被误报为资源损坏，造成所有照片都不能导入。模型长度、MD5 和风险输出校验仍然生效。

## 拦截范围

1. 相册和拍照选图后，先检测，后设置页面图片路径。未通过的原图不会进入页面、主体提取或取色流程；换图失败保留此前已通过的图片。
2. 未在当前会话检查过的旧作品缩略图显示「点开查看」，不在启动时排队检测全部 20 份作品；打开结果页时检查，通过后才展示和自动保存。
3. 两种导出都先检查图纸，再绘制、生成文件和写入相册。不能靠旧文件缓存绕过检查。
4. 安装包的固定样板按完整网格、色值、名称、用量和来源匹配；只填写 `templateId` 或旧版检测标记不能豁免检查。
5. 已通过图纸的缓存仅存于内存，包含所有实际格子的颜色、模型版本及规则版本；修改内容后需要重新检查，应用重启后旧作品重新检查。不会保存分类或分数。

违规只显示「内容含违规信息」，不显示命中分类、概率或原始推理错误。模型读取、校验、加载、输出格式或超时失败均不会放行；可取消或重试。图片检测排队执行，避免多个模型同时抢占手机内存，空闲 120 秒后释放模型。会话内最多缓存六份已经通过的实际归一化输入，逐字节相同才复用，换图仍解码并逐个处理裁片；不会依据路径或持久化标记放行。单次任务从开始解码起最多等待 60 秒；取消中的解码或推理会释放队列，迟到结果不能放行或覆盖新图片。排队任务也可取消，且不会终止另一张正在检测的图片。

## 模型与限制

模型输入采用上游的 RGB / 255、双线性对齐端点缩放，接口为 `rgb float32[1,3,224,224] → probabilities float32[1,5]`。透明图片先合成到白底，避免隐藏的透明像素影响识别；宽长图额外检查至多四个方形裁片。

内部类别顺序为 Drawing、Hentai、Neutral、Porn、Sexy。当前策略为 Hentai 或 Porn ≥ 0.30，两者之和 ≥ 0.40，或 Sexy ≥ 0.70 时拦截。这是产品初始阈值，未经本项目大规模真实图片集校准。输出必须是长度正确、有限、范围合法且总和接近 1 的概率，否则按检测失败处理。调整阈值需同步更新规则版本并重新验证误判与漏判。

分类模型会误判和漏判，尤其是低分辨率拼豆图、局部小图、复杂拼图、医学与艺术图片；它不覆盖微信所有违规类型，也不是可对抗篡改客户端的服务端审核。本地检测不能替代微信明确要求的安全 API。需要向平台如实说明本地实现，取得场景复核结论，或在另行授权后接通官方接口。

## 离线重建

```sh
python3 -m venv /tmp/perler-safety-build
/tmp/perler-safety-build/bin/pip install numpy onnx
/tmp/perler-safety-build/bin/python scripts/adapt-safety-model.py
```

脚本只读取仓库内固定来源的模型 JSON 和量化权重，检查 SHA-256 后转换，不下载模型、不重新训练、不再次量化权重。输出 ONNX 的源码缓存位于 `scripts/safety-source/nsfw-runtime.onnx`，运行包只使用压缩资源。普通 `npm run build:*` 无需 Python。

微信 Worker 内的卷积加速内核源码位于 `scripts/build-safety-wasm.mjs`，运行 `npm run build:safety-wasm` 可用锁定的 wabt 重新生成 `src/static/safety/convolutions.wasm`。它不含新模型，使用 float64 累加、float32 输出，与 CPU 保持舍入点一致。内核随主包放在 Worker 目录外，固定内存 8 MiB；不可用时继续使用同模型 CPU。Worker 传输以有序 Base64 分块完成，避免大 ArrayBuffer 的原生序列化阻塞；首次模型解压保留长度及 MD5 验证、分步进度和取消检查。

## 验证边界

- 自动测试覆盖风险分数拦截、无效输出拒绝、原生缓存修复、资源完整性、模型加载取消、解码卡住后的取消/超时/重试、排队取消隔离、选图等待/失败/取消、旧作品和两种导出拦截。测试用风险分数是构造数据，不是色情图片识别准确率证明。
- ONNX 与上游 TFJS 在同一固定输入上逐项对比，最大绝对差约 `4.77e-7`。这证明该输入上的转换数值一致，不证明所有图片上的识别效果。
- 提审前仍需在 iOS、Android 微信真机验证资源加载、推理、正常照片、平台允许的违规测试用例、超时、取消及权限恢复。不得将浏览器测试或构建通过写成真机审核通过。
