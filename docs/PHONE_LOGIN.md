# 手机号验证码登录

2026-11-15：客户端与独立后端代码已完成，真实短信服务尚未开通和联调。本轮没有购买短信、发送真实短信、修改线上环境或部署服务器。

## 选型

初期建议 **阿里云短信按量付费**。核查的官方公开验证码价格为每条 0.045 元（月量不超过 10 万条），1,000 条约 45 元；无需预购大包。腾讯云适配保留为备选。完整价格、签名资质要求与官方来源见 [服务比较](SMS_PROVIDER_COMPARISON_2026-11-15.md)。

先完成资质审核，再考虑充值。阿里云和腾讯云当前新签名需要企业资质或企业授权；只有个人实名认证不能保证正式发送。签名、模板审批和供应商控制台可用状态均需实际确认。

## 用户流程

- 登录页默认手机号与六位验证码，先同意隐私说明，再获取验证码；成功验证后新号码自动创建普通账号。
- 验证码 5 分钟有效，60 秒后可重发；同一验证码最多错 5 次，用过的验证码不能再次登录。
- 老用户选择“使用原账号密码登录”，登录后进入“账号设置 → 绑定手机号”。绑定保留原账号 ID、作品和权益，不会将两个已有账号自动合并。
- 已绑定号码不能自行更换，当前交由客服核实处理。管理员仍使用原密码登录。
- 短信未配置时明确显示暂未开放，保留原账号登录和游客做图，不提供固定验证码或虚假的发送成功。

## 开通与发布顺序

1. 在阿里云短信控制台核实主体资质，申请真实业务签名及验证码模板。建议短模板：“您的验证码为 ${code}，5 分钟内有效，请勿向他人透露。”模板仅使用 `code` 变量，以最终审核结果为准。
2. 为独立后端创建仅有 `dysms:SendSms` 权限的 RAM 凭据。密钥只填入后端服务器环境文件，不放入移动端、不提交到 Git，也无需发到聊天里。
3. 独立后端目录为同级 `perler-beads-backend/`，按其中 `docs/SMS_LOGIN.md` 配置 `SMS_PROVIDER=aliyun`、`SMS_SECRET_ID`、`SMS_SECRET_KEY`、`SMS_SIGN_NAME`、`SMS_TEMPLATE_ID`、`SMS_CODE_SECRET`。阿里云不需要 `SMS_SDK_APP_ID`。签名和模板名称必须与获批内容一致。
4. 备份数据库，在独立后端安装新依赖并运行 `npm run migrate`，执行新增 `003_phone_login.sql`，再重启服务。不要将客户端上传到后端服务器。
5. 检查 `/health/ready` 及 `/api/v1/config` 的 `smsLogin`。`true` 仅说明配置齐全，不证明短信能送达；还须检查余额、签名、模板和受限凭据权限。配置费用告警。
6. 经号码持有人同意，用自己的手机号发送一次短信，验证收到短信、错误码、重发、成功登录、退出重登及旧账号绑定。然后进行 Android 和微信真机验收。

验证码发送与校验均由独立后端完成；图纸转换仍在设备执行。前端隐私说明按阿里云短信填写，如更换服务商须同步更新。正式微信版仍需要备案 HTTPS 合法域名、官方内容安全处理和真实运营信息；短信接入不能替代这些要求。

## 本轮验证

- 前端 144 项自动测试通过，其中手机验证码组件 10 项，另有账号返回、切换账号、绑定更新和本机存储失败回归。
- 独立后端 43 项自动测试通过，其中短信 18 项，覆盖供应商请求、校验、过期、重放、并发、限流、旧账号绑定、工作人员限制。数据库测试使用本地隔离 schema；供应商使用注入的测试替身。
- H5、App 资源、微信小程序生产构建通过；9 项发布静态检查通过。App 资源不是正式签名 APK，静态检查不表示已满足上架条件。
- Chromium 320 / 390 / 430 CSS px 检查无横向溢出；使用模拟 API 操作发送、错误验证码、改正后登录、绑定、未开通提示、原账号入口及游客返回。模拟 API 不证明供应商真实发送成功。
- 页面操作发现并修复：直接进入登录页成功后未返回“我的”；uni-app 输入节流导致快速改码后可能提交旧值。输入失焦与键盘确认现在同步最新验证码，保留开头的 0。
